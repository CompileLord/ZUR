# S2 audit — actionable gaps

Scope: S2 tasks marked `done` in `tasks.json`, checked against `PRD_V2.md`, `design.md`, `rules_strictly.md`, and their cited implementation. Findings below are confirmed by static code inspection. No product files or task statuses were changed; no test suite was run.

| Task | Severity | Requirement and evidence | Recommended fix |
|---|---|---|---|
| T029–T031, T034–T037, T039, T048–T049, T052 | **Blocker** | Phase B requires a working author-to-student browser journey (PRD §20). The routed app never imports or calls the authored P21/P22/P23/P24/P25/P26/P31 components. Its S3 fallback renders a fixed `Python foundations` dashboard for `/teach`, `/learn`, and `/learn/courses` ([`packages/web/src/main.ts:1176`](../../packages/web/src/main.ts#L1176)); its S5 fallback renders a fixed sample tree and editor for builder/settings/editor routes ([`packages/web/src/main.ts:1468`](../../packages/web/src/main.ts#L1468)). P26 routes to the S4 fallback instead of `AuthorPreviewPage` ([`packages/web/src/router/routes.ts:76`](../../packages/web/src/router/routes.ts#L76), [`packages/web/src/main.ts:1202`](../../packages/web/src/main.ts#L1202)). The dedicated author page components exist but are disconnected. | Wire each S2 route to authenticated course and enrollment data, its real page component, and working actions. Exercise the complete journey in the browser before retaining the S2 `done` status. |
| T047 | **Blocker** | PRD §10 requires quiz completion only after a correct submitted answer and Python completion only after a server pass. `POST /api/enrollments/:id/steps/:id/complete` accepts any step ID ([`packages/server/src/server.ts:1585`](../../packages/server/src/server.ts#L1585)); `markStepComplete` checks only enrollment ownership/status, then writes `is_completed = 1` without checking the step's pinned version or type ([`packages/server/src/services/learning-progress-service.ts:50`](../../packages/server/src/services/learning-progress-service.ts#L50)). A learner can mark an unpassed assessment complete and can write progress for an unrelated step ID. | Restrict this endpoint to Theory/Video steps in the enrollment's pinned snapshot. Award Quiz/Python completion only from the authoritative successful grading paths, with a transactional eligibility check. |
| T039 | **High** | PRD §8.3 and AC-05 require owner-only draft preview. The preview API authorizes `courseId` and fetches `stepId` independently; it never verifies the step belongs to that course ([`packages/server/src/server.ts:1435`](../../packages/server/src/server.ts#L1435)). An owner of one course who knows another course's step ID can request that step's draft content. | Resolve the step through its lesson/module and require the requested course ID and authenticated owner to match before returning any metadata or content. Add a cross-course denial check. |
| T033 | **High** | PRD §11 sets a 10 MB image budget and requires validation of actual content type, dimensions, and processing limits. The service enforces 5 MiB ([`packages/server/src/services/media-service.ts:13`](../../packages/server/src/services/media-service.ts#L13)), trusts the supplied MIME after allowlist membership, and substitutes `800 × 600` if dimension parsing fails ([`packages/server/src/services/media-service.ts:53`](../../packages/server/src/services/media-service.ts#L53), [`packages/server/src/services/media-service.ts:103`](../../packages/server/src/services/media-service.ts#L103)). Malformed bytes can be stored as `ready` without a decode or dimension bound. | Align the budget with the PRD, decode and verify actual image bytes/type, enforce dimension/decompression limits, and mark assets ready only after processing succeeds. |
| T041 | **Medium** | PRD §8.3 and design P27 require duplicate publish clicks to represent one publication operation. Idempotency is held only in a process-local map keyed solely by the caller's string ([`packages/server/src/services/course-publication-service.ts:60`](../../packages/server/src/services/course-publication-service.ts#L60), [`packages/server/src/services/course-publication-service.ts:266`](../../packages/server/src/services/course-publication-service.ts#L266)). A restart loses the key; reuse of the same key on another course can return the first course's receipt. | Persist publication idempotency records in the transaction, scoped to owner/course and request identity, and reject key reuse with a different payload. |

Verification summary: These are implementation-path defects visible without runtime assumptions. The cited S2 test files do not establish the required browser journey or close the endpoint gaps above. Live integration, keyboard, screen-reader, and mobile checks remain unverified in this audit.
